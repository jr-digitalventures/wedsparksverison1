## WedSparks Website Page Structure

# Public / Discovery Pages

## Homepage

The main public-facing homepage for WedSparks, introducing the platform and directing couples and vendors into the relevant parts of the website.

---

## How It Works — Couples

A public-facing page explaining how WedSparks works for couples.

It should explain the full journey, such as:

* Create your wedding profile
* Tell WedSparks about your wedding
* Discover suitable vendors
* Filter vendors by availability
* Save and compare vendors
* Contact vendors
* Receive quotes
* Make bookings
* Manage the wedding through the planning dashboard

The purpose of this page is to clearly communicate the value of the platform before a couple creates an account.

---

## How It Works — Vendors

A public-facing page explaining how WedSparks works for wedding vendors.

It should explain things such as:

* Create a vendor account
* Build a public profile
* Add pricing and packages
* Add portfolio examples
* Manage availability
* Receive enquiries
* Communicate with couples
* Create and send quotes
* Manage bookings
* Collect and manage reviews

---

# Couple Discovery Pages

## Marketplace Search

The main search page where couples can browse and discover wedding vendors and suppliers.

A useful comparison would be a recruitment website's **Search Jobs** page.

This is the core marketplace experience, allowing couples to search, filter and explore different types of wedding vendors.

### Availability Search Feature

Availability should be built directly into the main marketplace search rather than operating as a separate page.

Couples should be able to toggle between:

* **Browse all vendors**
* **Show vendors available on my wedding date**

If the couple has already entered their wedding date in their profile, WedSparks could automatically use that date. Otherwise, they could select a date directly within the search.

The marketplace results would then only show vendors who have marked themselves as available on that date.

The existing marketplace filters could still work alongside this, including:

* Vendor category
* Location
* Price range
* Style
* Rating
* Services/features
* Availability

This keeps vendor discovery within one central marketplace while making availability one of the strongest ways couples can refine their search.

---

## Vendor Category Page — Dynamic

A dedicated page for each vendor category, such as:

* Wedding venues
* Florists
* Photographers
* Celebrants
* Caterers
* Entertainment

These pages would primarily support SEO while also helping couples browse vendors within a specific category.

Each page could include a short SEO-focused introduction about the service, followed by marketplace search results automatically filtered to that vendor category.

---

## Vendor Public Profile Page — Dynamic

The public-facing profile page for each individual vendor.

A useful comparison would be an Airbnb listing page.

Once a couple clicks on a vendor from the marketplace, they would land here to explore the business in more detail.

The page would include:

* Business information and description
* Pricing and packages
* Key features and services
* Portfolio/examples of previous work
* Availability calendar
* Reviews
* Enquiry and messaging options
* Booking options

Couples would be able to contact the vendor directly through the WedSparks messaging system to make an enquiry or progress towards a booking.

---

## Vendor Comparison

Couples should be able to select multiple vendors and compare them side by side.

The comparison could include:

* Pricing
* Packages
* Location
* Availability
* Reviews
* Services
* Key features
* Minimum spend
* Portfolio information

This would make it easier for couples to evaluate shortlisted vendors without constantly moving between different profile pages.

---

## Personalised Wedding Recommendations

A dedicated recommendation experience based on information stored within the couple's wedding profile.

Couples could provide information such as:

* Wedding date
* Location
* Budget
* Guest count
* Style
* Priorities
* Preferred vendor types

WedSparks could then recommend vendors that are particularly relevant to their wedding.

This could initially operate through structured filtering and eventually become more personalised using AI.

---

# Couple Account Pages

## Couple Dashboard

The main overview/control centre for couples once they are logged in.

The dashboard should provide a high-level overview of everything happening with the wedding rather than containing the full functionality of every feature.

For example:

* Wedding countdown
* Budget summary
* Guest/RSVP summary
* Upcoming planning tasks
* Recently saved vendors
* New messages
* Outstanding quotes
* Confirmed bookings
* Recommended vendors

Each section can then link into its own dedicated page.

---

## Saved / Shortlisted Vendors

This functionality is part of the couple dashboard ecosystem.

Couples should be able to save vendors while browsing the marketplace and then access their complete shortlist from their account.

The dashboard can display a summary of saved vendors, while the dedicated Saved Vendors section/page provides the full shortlist.

---

## Messages / Inbox

Messages should operate as their own section within the couple dashboard/account area.

Selecting Messages from the dashboard navigation should open the full messaging interface.

Couples should be able to:

* View conversations
* Contact vendors
* Respond to messages
* Receive attachments or information
* Access conversations relating to enquiries, quotes and bookings

The dashboard itself can simply display unread messages or recent conversations.

---

## Bookings & Quotes

A dedicated section where couples can manage the commercial side of their vendor relationships.

This could include:

* Enquiries sent
* Quotes received
* Quotes awaiting a decision
* Accepted quotes
* Confirmed bookings
* Booking status
* Payment/deposit information where applicable
* Booking documents

The dashboard should show a simple summary, while the full Bookings & Quotes page contains the detailed information.

---

## Budget Planner

A dedicated planning section for managing the wedding budget.

Couples should be able to:

* Set their total wedding budget
* Allocate budgets to different categories
* Add estimated costs
* Track actual costs
* Connect confirmed vendor bookings to expenses
* See remaining budget
* Track deposits and upcoming payments

The couple dashboard can show a high-level budget summary, while the Budget Planner contains the full functionality.

---

## Wedding Timeline / Checklist

A dedicated planning section that helps couples understand what they need to organise and when.

The timeline should ideally use the couple's wedding date to create relevant planning milestones.

For example:

* Research venues
* Book photographer
* Organise catering
* Finalise guest list
* Send invitations
* Confirm vendor arrangements

Couples should also be able to:

* Mark tasks as complete
* Create custom tasks
* Set deadlines
* Receive reminders

The dashboard can show upcoming tasks, while the complete timeline/checklist has its own section.

---

## Guest List

A dedicated area for managing wedding guests.

Potential functionality includes:

* Add and remove guests
* Group guests into households
* Store contact information
* Track RSVPs
* Record dietary requirements
* Record plus-ones
* Assign table/seating information later if required

---

## Invitations

A dedicated area for creating and managing wedding invitations.

Potential functionality includes:

* Create digital invitations
* Email invitations
* Track whether invitations have been sent
* Connect invitations with the guest list
* Link guests to digital RSVP forms

---

## Couple Account & Settings

A dedicated settings area containing things such as:

* Personal information
* Wedding information
* Partner information
* Email address
* Password
* Notification preferences
* Email preferences
* Privacy settings
* Account management
* Delete account

---

# Vendor Account Pages

## Vendor Dashboard

The main overview/control centre for vendors once they are logged in.

Rather than putting every piece of functionality onto one large screen, the dashboard should provide a snapshot of important activity.

For example:

* New enquiries
* New messages
* Outstanding quotes
* Upcoming bookings
* Profile completion
* Availability
* Recent reviews
* Marketplace/profile performance

Each area can then link to the relevant dedicated section.

---

## Vendor Profile Management

The main area where vendors build and maintain their public WedSparks profile.

This could include:

* Business information
* About section
* Service categories
* Locations serviced
* Portfolio
* Photos
* Videos
* Key features
* Pricing
* Packages
* Contact information

Changes made here would update the vendor's public-facing profile.

---

## Vendor Availability

A dedicated section where vendors manage their availability calendar.

Vendors should be able to:

* Mark dates as available
* Mark dates as unavailable
* View confirmed bookings
* Block out dates
* Manage availability across different services where required

This information would connect directly with the marketplace availability filter.

---

## Vendor Messages / Inbox

Messages should operate as their own section within the vendor dashboard/account area.

Selecting Messages from the dashboard navigation should open the full messaging interface.

Vendors should be able to:

* View customer enquiries
* Respond to couples
* Send attachments
* Discuss quotes
* Manage conversations relating to bookings

The main vendor dashboard can simply show new or unread messages.

---

## Vendor Quotes

A dedicated area for creating and managing quotes.

Vendors should be able to:

* Create quotes
* Select packages/services
* Add custom items
* Set pricing
* Send quotes to couples
* View quote status
* Edit or withdraw quotes
* See whether a quote has been accepted or declined

---

## Vendor Bookings

A dedicated area for managing confirmed bookings.

This could include:

* Couple details
* Wedding date
* Booking status
* Services booked
* Agreed pricing
* Payment/deposit information
* Important dates
* Relevant documents
* Notes

The vendor dashboard can provide an upcoming bookings summary.

---

## Vendor Pricing & Packages

A dedicated section where vendors create and manage their pricing options.

They could:

* Create multiple packages
* Set starting prices
* Define package inclusions
* Add optional extras
* Update pricing
* Decide which pricing information appears publicly

---

## Vendor Reviews

A dedicated area for managing reviews received through WedSparks.

Vendors could:

* View reviews
* Respond to reviews where appropriate
* See overall review information
* Manage review requests if this functionality is introduced

---

## Vendor Account & Settings

A dedicated settings area containing things such as:

* Account details
* Business details
* Login information
* Password
* Notification preferences
* Email preferences
* Billing/subscription information
* Privacy settings
* Team/account permissions later if required
* Account management

The dashboard should act as an **overview and control centre**, while each major feature should have its own page or route.

### Couple Account

* Dashboard
* Budget Planner
* Guest List
* Invitations
* Saved Vendors
* Messages
* Bookings & Quotes
* Wedding Timeline / Checklist
* Account & Settings

### Vendor Account

* Dashboard
* Profile Management
* Availability
* Messages
* Quotes
* Bookings
* Pricing & Packages
* Reviews
* Account & Settings

This can still feel like one seamless dashboard experience because the same navigation can remain visible throughout the account area.
